0. SERVER ACCOUNTS, SESSION COOKIES, SCORE PERSISTENCE & LEADERBOARD
--------------------------------------------------------------------------------
- Backend (server.py):
  * Added POST /api/register, POST /api/login, POST /api/logout, GET /api/me.
  * Sessions are real server-side sessions: a random token is sent in an
    HttpOnly, SameSite=Lax cookie (wh_session), and only its SHA-256 hash is
    stored in SQLite.
  * Added POST /api/solve. The server validates each riddle answer and records
    every solve once in the `solves` table, then adds the coins to the account.
    Clients can no longer set their own points.
  * Added POST /api/profile, POST /api/progress (hint sync only),
    POST /api/reset and GET /api/puzzles.
  * GET /api/leaderboard now ranks players by saved coins and marks the
    current player with isYou.
- Database (db/init_db.py):
  * Added password_hash, email, timestamps and progress columns; existing
    plaintext passwords are migrated to salted PBKDF2 hashes on startup.
  * Added hashed `sessions` and per-puzzle `solves` tables.
  * Migrates legacy JSON solved-puzzle lists into the solves table.
- Frontend:
  * login.html: real login + registration tabs; removed the IndexedDB fallback.
  * session.js v2: boot/register/login/logout, server-validated solvePuzzle,
    profile updates, reset, leaderboard, and a shared boot promise.
  * puzzle-engine.js: every correct answer is saved through /api/solve before
    the reward banner appears; offline/session-expired fallbacks are explicit.
  * leaderboard.html: current-player highlight, "your standing" strip, login
    CTA and 20-second auto-refresh.
  * profile.html/js: display-name/email saved to the account; reset now clears
    server-side progression; stats show solved count out of the total trials.
  * Added session.js to every page and bumped cache-busting script versions.

17. isSolved() IN THE CONSOLE — EASY-ONLY FLAG EXPLOIT
--------------------------------------------------------------------------------
- New global helper (public/js/check-is-solved.js v=3):
  * `isSolved()` claims the final trial is solved and returns the Queen's flag
    directly in the browser console.
  * `isSolved(true)` behaves the same; `isSolved(false)` returns 0.
  * `isSolved(number, solved)` keeps the old prize semantics (50/100/200, with
    the flag only for ordinal 30). `checkIsSolved(number, solved)` remains as a
    backwards-compatible alias for the same endpoint.
  * The script is now loaded by index.html and by all three chamber pages.
- The function is only vulnerable in Easy:
  * POST /api/check-is-solved (and the new /api/is-solved alias) inspects the
    request's Referer header before reading the client's `solved` claim.
  * Requests from /challenges/easy/ and the landing page are allowed and trust
    the claim, so `isSolved()` returns the flag there.
  * Requests from /challenges/medium/ or /challenges/hard/ get HTTP 403 with
    `{"immune": true}` and no prize/flag. Missing or unrecognised Referer
    headers are also refused, so the shortcut cannot be replayed from curl or
    another page.
  * Browsers do not let page JavaScript forge the Referer header, so Medium and
    Hard players cannot spoof their way past the check from the console.
- `isSolved` is exposed on `window` (alongside `checkIsSolved`,
  `checkIsSolvedAsync` and `WonderCheckIsSolved`), so the player can type it
  directly in DevTools on the Easy Chamber page.
- Updated the Mad Hatter's Easy hints (public/js/wonderhack-easy-hints.js and
  public/data/wonderhack-easy-hints.json) to teach `isSolved()` and note that
  Medium/Hard are immune.
- Bumped check-is-solved.js to v=3.
